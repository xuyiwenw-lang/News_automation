## 环境要求

- Python 3.11 或更新版本（建议 3.11）。
- 飞书企业自建应用，以及应用有权访问的源表和目标表；两张表须位于同一个多维表格应用下。
- 应用需要读取表字段及记录、创建与更新记录、删除目标表重复记录的权限；开启高级权限时也要授权对应表。
- 可用的 DeepSeek API Key，以及运行环境到飞书、DeepSeek 和文章来源网站的网络访问。

## 配置表格

程序启动时检查字段名称和类型，不会自动创建或修改表结构。字段名须与下表完全一致。

### 源表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 内容概括 | 文本 | 必填，原标题或摘要 |
| 公司 | 文本 | 可为空，模型补全 |
| 分类 | 文本或单选 | 可为空，模型补全 |
| 来源 | 文本 | 文章来源 |
| 链接 | 文本或超链接 | 合集必须有可访问的文章链接 |
| 时间 | 文本或日期 | 文本推荐 `2026-09-29` |
| 是否已清洗 | 文本或单选 | 空或“否”待处理，成功后设为“是”；不是复选框 |
| 清洗计划 | 文本 | **新增**，程序保存固定拆分结果，用于重试；初始留空 |

### 目标表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 内容概括、公司、来源 | 文本 | 清洗后的新闻信息 |
| 分类 | 文本或单选 | 使用下方分类选项 |
| 链接 | 与源表相同 | 保留原链接 |
| 时间 | 与源表相同 | 保留原时间 |
| 清洗方式 | 文本或单选 | 单条可为空；拆分、聚合、拆分后聚合 |
| 聚合链接 | 文本 | 多个来源以 `、` 分隔 |
| 评分 | **数字** | 1–5 分；若旧表使用文本或单选，请先迁移为数字字段 |
| 评分依据 | 文本 | **新增**，记录本次评分输入的指纹 |
| 清洗键 | 文本 | **新增**，关联源记录及拆分序号；聚合后保留所有键 |
| 待删除记录 | 文本 | **新增**，保存已合并但未确认删除完成的恢复信息 |

分类选项：`AI营销`、`应用：商业化`、`应用：用户`、`应用：Agent`、`应用：其他`、`模型`、`内容消费`、`观点类`。单选字段请预先配置这些选项；“是否已清洗”包含“是”“否”。

辅助字段可以在日常视图中隐藏。不要手工修改或清空这些字段，否则可能破坏重试追踪。

## 本地运行

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

编辑 `.env`，填写自己的值。原代码中的明文应用密钥应在飞书后台更换；删除代码中的密钥不会使旧密钥失效。

| 环境变量 | 必填 | 含义 |
| --- | --- | --- |
| FEISHU_APP_ID | 是 | 飞书应用 ID |
| FEISHU_APP_SECRET | 是 | 新的应用密钥 |
| FEISHU_APP_TOKEN | 是 | 多维表格应用的 app token |
| FEISHU_SOURCE_TABLE_ID | 是 | 源表 table ID |
| FEISHU_DEST_TABLE_ID | 是 | 目标表 table ID |
| DEEPSEEK_API_KEY | 是 | DeepSeek API Key |
| FEISHU_BASE_URL | 否 | 默认 `https://open.feishu.cn/open-apis`；Lark 使用 `https://open.larkoffice.com/open-apis` |
| NEWS_TIMEZONE | 否 | 新闻日期时区，默认 `Asia/Shanghai` |
| NEWS_LOOKBACK_DAYS | 否 | 历史去重回溯天数，默认 `7`，必须大于 0 |

程序从进程环境变量读取配置，不自动加载 `.env`。在 bash/zsh 中运行：

```bash
set -a
source .env
set +a
python main.py
```

`.env` 是 shell 配置文件，只加载自己维护的可信文件；包含特殊字符的值须正确加引号。运行入口统一为 `main.py`，避免绕过恢复和完成状态管理。

## GitHub 每日自动运行

1. 将代码上传至自己的 GitHub 仓库，确保 `.github/workflows/` 在默认分支上。
2. 在仓库 **Settings → Secrets and variables → Actions → Secrets** 中添加上表的 6 个必填环境变量，名称保持一致。不要把密钥填进 workflow 文件。
3. 如使用 Lark，在同一位置的 **Variables** 中设置 `FEISHU_BASE_URL`；可选设置 `NEWS_LOOKBACK_DAYS`。
4. 打开 **Actions → Daily news cleaning → Run workflow**，先手动运行一次，检查日志和表格结果。
5. 默认每天 **北京时间 09:17（UTC 01:17）** 触发。修改 `.github/workflows/daily-clean.yml` 中的 cron 即可调整时间。`NEWS_TIMEZONE` 控制新闻日期解析，不改变 cron 的触发时间。

定时和手动执行使用同一个并发组，前一次任务不会因新任务触发而被取消。每次先运行离线测试，再运行清洗。另一个 `Offline tests` 工作流在 push / pull request 时仅测试，不连接真实业务服务。

GitHub 定时任务可能延迟，且仅在默认分支运行；公共仓库连续 60 天没有活动时，定时任务可能被自动停用，详见 [GitHub 官方定时事件文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。失败时可从 Actions 日志定位问题并重新运行，或等待下一天重试。

## 中断恢复与限制

| 中断位置 | 下次运行的行为 |
| --- | --- |
| 拆分或字段补全失败 | 源记录仍待处理，不写入虚假结果 |
| 拆分计划已保存，只写入部分目标行 | 复用计划和已有清洗键，只创建缺失的目标行 |
| 创建请求超时，但服务器已保存 | 下次读取目标表，通过清洗键识别已保存结果 |
| 主记录更新失败 | 不删除重复行 |
| 合并成功，删除失败或只删除部分 | 先读取恢复信息，只删除仍存在且未被修改的重复行 |
| 重复行在中断后被人工修改 | 停止删除，保留记录供人工核查 |
| 评分失败 | 不写入默认 1 分；成功记录的评分进度已保留 |
| 源表完成标记失败 | 重跑复用目标输出及合并后保留的清洗键 |

此恢复机制以单个写入进程和下次读取能看到已提交数据为前提，不是跨系统事务。请勿同时在本地、其他仓库或其他调度器对同一张表运行清洗；运行期间也不要人工修改参与聚合的记录。GitHub 并发组只能约束本仓库的工作流。

其他边界：

- 合集网页无法访问、命中验证页或没有足够正文时任务失败，需修复来源后重跑；不根据标题编造整篇新闻。
- 空摘要不会自动删除，需要人工修复。模型仍可能出现语义判断或评分偏差，建议在副本表上完成首次验收。
- 正文超过 50,000 字符、聚合输入超过 60,000 字符，或单条恢复数据超过 80,000 UTF-8 字节时明确失败，不静默截断。大量历史未评分记录首次迁移可能触发上限；应先在隔离的副本中分批处理。单纯缩短回溯期不会排除未评分记录。
- 旧版本已经“标记完成但没成功写入”的数据，需要人工找回后重新设为待处理。旧目标记录没有清洗键，首次接入应先核查对应关系；无法自动推断过去失败写入的来源关系。
- 源记录的拆分计划保存后视为固定快照；修改源新闻不会自动覆盖该计划。需要修订时先完成或人工核对已有输出，不要直接清空计划重跑。
- 每次去重会扫描目标表并调用模型。数据量增大时应评估 API 用量；当前版本适合规模有限的日常新闻表。

## 离线测试

```bash
python -m unittest discover -s tests -v
```

测试使用内存表格和模拟模型，不需要真实密钥，不访问表格，不消耗模型额度。覆盖部分写入恢复、创建超时、聚合更新和删除失败、无新数据补评、合并后重评、非法模型输出、富文本字段、跨周日期以及 API 业务错误。

## 项目结构

```text
main.py                  完整流程编排
split_news.py            拆分、字段补全、持久计划与清洗键
aggregate_news.py        语义聚合、日期解析、删除恢复
score_news.py            评分及评分依据校验
feishu.py                飞书 API、分页与表结构检查
config.py                环境变量配置
common.py                字段转换与模型响应校验
editorial.py             分类、归一化、聚合和评分规则
requirements.txt         Python 依赖
.env.example             无密钥的配置示例
tests/test_pipeline.py   离线回归测试
.github/workflows/       每日清洗和测试工作流
```

`.gitignore` 排除了 `.env`、虚拟环境、缓存，以及原目录中的 `to_split.json`、`split_results.json`、`write_log.json`。这三个历史数据文件保留在本地，不是运行依赖，不随正常 Git 提交上传。
